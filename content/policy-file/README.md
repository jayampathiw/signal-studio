# The Policy File — case project convention

One directory per case: `content/policy-file/<case-slug>/`

```
<case-slug>/
  case.json       — case metadata + scene list (see shape below)
  documents/       — source document images (you supply, already redacted)
  vo/              — per-scene Kokoro narration .wav (auto-generated by
                     assemble-case.mjs if missing; commit them once generated
                     so re-renders are deterministic)
  output/          — rendered .mp4 (assemble-case.mjs writes here)
```

## `case.json` shape

```json
{
  "caseId": "case-001-denied-claim",
  "title": "They Denied Her Claim Over One Word",
  "description": "A homeowner's insurance claim was denied over a single clause buried on page 14.",
  "sourceCitation": "Policy #XXXX, Exhibit A (redacted)",
  "scenes": [
    {
      "id": "s1",
      "imagePath": "policy-page-14.jpg",
      "captionText": "The policy promised full coverage. The fine print said otherwise.",
      "narrationText": "Spoken script for this scene — captionText is used if omitted.",
      "zoomFrom": { "x": 0, "y": 0, "width": 1, "height": 1 },
      "zoomTo":   { "x": 0.06, "y": 0.28, "width": 0.55, "height": 0.1 },
      "highlight": { "x": 0.06, "y": 0.283, "width": 0.55, "height": 0.035, "fromFraction": 0.5, "toFraction": 0.75 }
    }
  ]
}
```

**Every scene should carry a document** — the brand's core identity is "the document
carries the video," not two isolated evidence beats in an otherwise-generic
voiceover. A scene with no `imagePath` of its own automatically carries the
*previous* scene's document forward (never renders blank) — use that deliberately
for a connective beat, don't rely on it to paper over a missing asset.

**Scene duration is derived from the actual narration audio** (measured after Kokoro
synthesis, + a small tail pad), not authored — `durationSecs` in case.json is only a
fallback for a scene with no narration at all (e.g. a short silent cut to a new
document). Don't hand-guess a duration for a narrated scene; it will either leave
dead air (guess too long) or cut the narration off mid-sentence (guess too short).
`holdExtraSecs` adds extra time on top of the measured narration length, for a scene
that needs a deliberate hold (e.g. a closing shot before the outro).

**Zoom** (`zoomFrom`/`zoomTo`, both optional): document-page regions (fractions,
same coordinate space as `highlight`) the camera pushes/pans between over the scene.
Both default to the full page. Omit `zoomFrom` to continue from wherever the
*previous* scene's camera ended, if it's the same document (e.g. scene 2 pushes in,
scene 3 continues the push/pans elsewhere, scene 5 pulls back out) — that continuity
is automatic, only set `zoomFrom` explicitly to break it (e.g. a fresh document
should start back at the full page).

**Highlight** coordinates are fractions of the document page (the whole page is
always shown, letterboxed if not 16:9 — never cropped), set manually during document
prep, not auto-detected. Timing is `fromFraction`/`toFraction` (0–1 of the scene,
resolved against the measured duration — use this, not fixed seconds, since duration
isn't known until narration is synthesized) or `fromSec`/`toSec` for a fixed timing.
`opacity` (0–1, default 0.55) caps the highlight's intensity — dim it for a
carried-over highlight in a later scene (e.g. "still relevant, but we've moved on").

## Commands

```bash
# Render (Remotion CaseFile composition, requires --experimental-strip-types)
pnpm --filter @signal-studio/video assemble-case -- --dir content/policy-file/<case-slug>

# After reviewing output/<caseId>.mp4, register + upload for the dashboard publish flow
pnpm --filter @signal-studio/video register-case -- --dir content/policy-file/<case-slug>
```

Requires `FB_PAGE_ID_POLICY_FILE` / `FB_ACCESS_TOKEN_POLICY_FILE` set for the
Facebook publish step (dashboard-driven, not part of these scripts).
